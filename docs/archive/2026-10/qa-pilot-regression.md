# QA pilot evidence regression

`tools/playtest-relay.client.luau` records server outcomes without replacing them. A terminal entry stays latched through the UI's 1.2 second flight-view hold. Distinct `Started.aircraft` instances create attempts; duplicate starts for a seen aircraft and duplicate terminal events do not create or rewrite entries. Initial installation into an active flight can create its first entry.

`kills` remains the raw total from `MissionFinished`. `AirKills` subtracts ground kills; `RequiredAirKillsObserved` also subtracts `optionalKills` (optional air kills). `ResultValid` requires finite nonnegative integer counters, sufficient required air kills, exact required ground kills, a positive elapsed time below the mission limit, and the supplied `completedPhases` matching the expanded catalog total. Missing older/fallback counters leave validation false; they do not change the authoritative Completed/Failed outcome. Phase totals are never inferred into the evidence.

After `bun run build` and `bun tools/test-relay-offline.ts`, run `bun tools/test-playtest-relay.ts` with the official standalone Luau CLI available via `LUAU_BIN`. This executes the actual LocalScript inside a deterministic mocked environment, using the real compiled mission catalog. It covers normal and late installation, starts/results duplicated during the active hold, stop/retry numbering, failures, M20 air9/ground2 and M27 air5/ground1/seven expanded phases, optional air kills, incomplete evidence, live throttle restoration and inert result teardown. The shared offline gate includes it without lowering existing thresholds.

Live detach releases the stick and restores the throttle captured before this pilot first controlled that flight. Result teardown does not restore throttle or resume a controller. No flight state, health, progress, unlock or server outcome is written.

Limits: these are mocked lifecycle contracts, not gameplay acceptance. No Studio, Rojo runtime or Roblox server is exercised. MissionFinished has no sortie identity, so an arbitrarily delayed terminal packet arriving after a subsequent start of the same mission cannot be distinguished by this tooling. Initial injection during an already-ended flight's UI hold likewise has no terminal history to inspect. Neither case justifies modifying the production protocol in this focused change.
