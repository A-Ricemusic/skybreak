## 2. Layout and scale

### HUD units and scale factor

Use **k = 0.96 studs per reference metre** (D-022), implementing D-015/D-016’s travel-time rule. Inferred HUD units remain separate: SPEED is treated as km/h and ALT/range as feet, following M02–M05. For an ALT reading *h*: `Y = 32 + 0.96 × 0.3048 × h`. Sea datum is proposed Y=32. A different terrain datum requires moving every target, gate and route together.

Reference cruise ~600 km/h =166.7 m/s →160 studs/s. Thus 1 reference km →960 studs; straight cruise 1 km takes ~6 s. This is calibration, **not proof of any distance below**. Match actual navigation time after authoring the map, including turns and target search.

## 5. Lighting and atmosphere

Bright blue daylight with broken white cloud and strong distance haze. Sun visible, sea dark blue; no storm or night lighting. (1:40:13; 1:44:23; 1:46:28).

- Start with a mission-owned environment preset. Main’s M04 inland-noon and M05 night-refinery presets are reusable infrastructure, not visual matches by default.
- Preserve sky/ground contrast, horizon haze and the target label/radar readability at combat altitude. Match sun height from the cited frames; azimuth is unresolved.
- Use bounded actual lights only where needed, with cheap emissive dressing for distant sources. Batch C’s night anchors are available; bright daylight missions do not need searchlights.
- No audio weather conclusions are drawn. Mist does not establish rain, and a dark grade does not establish midnight.

**Bounded implementation slice:** first build the approach and one target sector plus relevant route/exit landmark; compare actual Studio render to the cited source frames at matching altitude and framing. Then expand after checking silhouette, scale, material readability and regressions. Runtime success, target presence or TextFits does not establish appearance or flight feel.

**Performance:** apply existing coarse/fine LOD and sealed-shell budgets; calculate terrain jobs before building and measure load time and phone performance afterward. A theoretical estimate is not an observed Studio load. Keep targeting/AA independent of scenery LOD.
