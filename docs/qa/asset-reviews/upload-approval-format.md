# Upload approval evidence

Real runs fetch origin, use the canonical account state and lock, and reject --state-dir. An alternate directory is available only with --dry-run, whose control flow cannot read a key or send requests. Temporary overrides are restored after return/errors. Audio/voice remain permanently disabled. Each transport attempt, including 429 retries and status polls, rechecks the model HALT; POST attempts also repeat byte-bound review validation.

Authoritative decisions are every JSON file recursively under `docs/qa/asset-reviews/decisions/`. Records are objects with a single asset name, exportVersion, files (filename → SHA-256 for FBX and every embedded texture/dependency), reviewer, creator, reviewDate, policyLinks, integer score 10, verdict APPROVE, and sourceReview path. Duplicate JSON keys, multiple matching positive decisions, any matching REJECT/lesser score, inconsistent hash sets, local-only records, and locally modified evidence fail closed. A negative decision for a matching FBX hash wins regardless of date. Do not delete negative decisions to authorize an upload.

The export manifest lives with the asset as `export-manifest.json`, records its creator, version and full dependency hashes, and must agree exactly with the decision and existing approval metadata. Entire FBX bytes are pinned, including embedded data. External dependencies and the source review must match fetched origin/main; the FBX must also equal that merged asset. New evidence cannot authorize uploads until merged via PR. No working-tree or local-HEAD-only approval is accepted.

Reviewer identities must differ from the manifest creator and may not contain creator/self/implementation/author markers. These string and Git checks cannot prove independence absolutely. The orchestrator must assign a separate reviewer who inspects the exact exports, maps and assembled appearance under current Roblox policies, and merge that evidence via PR. Role descriptions in migrated manifests identify the historical implementation agent; they are not new identity attestations or new safety reviews. A score of 10 is the project's maximum judgment, not a moderation guarantee.
