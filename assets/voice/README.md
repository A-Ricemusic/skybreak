# Voice-over

ElevenLabs voices for every cutscene line (`src/shared/RelayStory.ts`) and every in-mission radio
line (`src/shared/MissionCatalog.ts`: beats, chatter, twists, hazards, group calls, ace stage/return
lines, plus the server's "pulled back to call his wing" calls). HUD system text is never voiced; the
trainee speaks in cutscenes only.

| File | What it is |
|---|---|
| `casting.json` | Speaker → premade voice, voice settings, model, spoken-form replacements, retakes, accepted STT homophones |
| `lines.json` | Generated by `bun tools/voice-lines.ts`: stable line id, speaker, exact on-screen text, spoken text |
| `voiceBank01-06.ogg` | Upload banks (mono Vorbis, ≤ 6.25 min, 0.25 s silence between lines) |
| `upload-plan.json` | Bank sha256, duration and every line's region |
| `transcripts.json` | Line id → speaker, exact text, spoken text, voice, bank |
| `provenance.json` | Line id → cache key, ElevenLabs request id, plan tier at generation |
| `stt.json` | ElevenLabs `scribe_v1` transcription of each bank; per-line word-match rate |
| `checklists/*.json` | Per-bank moderation pre-check and full transcript for the reviewer |
| `sampler.mp3` / `sampler.json` | One line per character (77 s) |

The game reads `src/shared/VoiceCues.ts` (generated cue table) and `src/shared/VoiceBanks.ts` (bank →
asset id, empty until uploaded; empty means silent). Pipeline and commands: `tools/voice.py --help`.
Raw ElevenLabs takes are cached outside the repo in `~/.skybreak-voice-cache` (keyed by
sha256 of voice + model + settings + text), so an edited line regenerates alone.

Uploading is the coordinator's job, after an independent reviewer writes `review.json`
(format in `tools/upload-voice.py`): `python3 tools/upload-voice.py --dry-run` first.

## Repair existing audio experience permissions

`tools/repair-roblox-audio-permissions.py` grants only `Universe` `10772984313`
`Use` access to the six current voice banks and eight current SFX assets. The
fixed 14-ID allowlist is tested against both approved upload manifests and
`VoiceBanks.ts` / `SoundBank.ts`. Every request sets `grantToDependencies: false`.
The script validates the configured official place and universe first. Default
mode is a network-free dry run; only `--execute` sends the single PATCH request.

The manual `repair-roblox-audio-permissions.yml` workflow uses the existing CI
`ROBLOX_API_KEY` only when its boolean `execute` input is true. After review and
availability of the workflow on the default branch, the operator can run:

```sh
gh workflow run repair-roblox-audio-permissions.yml --repo A-Ricemusic/skybreak --ref main -f execute=false
# Review the dry-run output, then explicitly apply:
gh workflow run repair-roblox-audio-permissions.yml --repo A-Ricemusic/skybreak --ref main -f execute=true
```

For a reviewed checkout with credentials already supplied securely in the
process environment (never put the key in command arguments or shell history):

```sh
ROBLOX_PLACE_ID=112911685457826 ROBLOX_UNIVERSE_ID=10772984313 python3 tools/repair-roblox-audio-permissions.py
ROBLOX_PLACE_ID=112911685457826 ROBLOX_UNIVERSE_ID=10772984313 python3 tools/repair-roblox-audio-permissions.py --execute
```

The [official endpoint contract](https://raw.githubusercontent.com/Roblox/creator-docs/main/content/en-us/reference/cloud/asset-permissions-api/v1.json)
requires `asset-permissions:write` plus authority over the assets and recipient
universe. A 403 requires checking that scope and creator authority on the
existing key; `asset:read` alone is insufficient. Do not broaden the recipient,
assets, action, or dependencies to work around a denial. The script never reads
local credentials or cookies, prints API bodies, or automatically retries.

Success requires exactly the 14 allowlisted success IDs and no reported errors.
Partial failures exit nonzero and can leave some grants applied. Transport or
response errors leave the result unconfirmed; review before retrying.
Per-asset output contains fixed IDs and sanitized outcomes only.

Metadata HTTP 200 and approved source audio do not prove experience-use access.
A successful grant response establishes the requested authorization but does not
prove audible playback. Rejoin the official published game in mobile Roblox
Player and check both voiced cutscenes and engine/UI/combat effects. Record
custom-asset fetch/authorization errors and compare against the audible built-in
water splash. This repair does not regenerate, upload, publish, or change game
code, and mobile playback remains a separate required verification.
